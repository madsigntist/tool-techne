# Defect Register

Every defect found in **{{TITLE}}**: what caused it, what was done about it,
what found it, and whether it came back.

This is not a changelog. A changelog lists what changed, by date. A register
says what is known to break and how well that is prevented, so sections are
kinds of defect, never dates. `scripts/lint-register.mjs` fails when the
counts at the bottom disagree with the rows.

## How to read this

Each fix is tagged for **how well it stops the problem coming back**:

| Tag | Meaning |
| --- | --- |
| **GATE** | a check now fails when the problem returns. It cannot come back unnoticed |
| **GEN** | the file is now generated by a script, so the mistake cannot be typed |
| **RULE** | a written rule. It only works if someone reads it |
| **POINT** | this one instance fixed, nothing stops it happening again |

**Found by** says what caught it: `gate` (a check in this tool), `tool`
(something outside it, like a linter), `eye` (someone noticed while
looking), `reviewer` (someone reviewing the result), `self-review` (found by
questioning an earlier conclusion).

**Again?** is the honest test of the tag. A RULE that comes back is a sign
to build a GATE.

**Positive-controlled** means a check was shown to fail when the problem was
put back, not only to pass. Write it down when you do it.
